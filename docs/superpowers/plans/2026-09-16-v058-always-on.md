# ZERO v0.5.8 Always-On Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make shadow/fork scanning restart-safe and observable as an always-on Linux service without adding private keys or live broadcasting.

**Architecture:** Add an RPC failover pool, runtime health/heartbeat snapshots, SQLite WAL mode, and service packaging. The scanner resumes from current chain state after restart and never replays stale candidates.

**Tech Stack:** Python 3.11, sqlite3 WAL, Docker, systemd.

**Spec:** `docs/superpowers/specs/2026-09-16-zero-roadmap-completion-design.md`

## Global Constraints
- No signer/private-key configuration.
- Highest retry cadence remains bounded; no busy loops.
- Service state is observability only; chain state remains source of truth.
